## tools/publish-pages.sh fix (commit `7b4156a`)

The workspace lists `crates/llm-life-lean` as a member, so `cargo metadata`
-- which `wasm-pack` runs even to build `crates/life` or `crates/llm-life`,
neither of which touches `lean` -- tried to resolve `lean`'s unpublished git
dependency and failed outright ("no matching package named `lean`").
`tools/build-lean.sh` already patched around this for its own crate with a
temporary `.cargo/config.toml`; `publish-pages.sh` now does the same thing
before the `crates/life`/`crates/llm-life` wasm-pack calls, removing the
patch right after so `build-lean.sh`'s own copy (which refuses to run if
one already exists) still works unmodified.

## Pushing and publishing (run from the main checkout, not this worktree)

1. Push `llm-web`'s `lean-release` branch (a separate decision; not done by this
   session):
   ```
   cd <llm-web checkout>
   git push origin lean-release
   ```
2. Pin the rev in `crates/llm-life-lean/Cargo.toml` on the `publish` branch
   (see above), commit:
   ```
   cd <llm-life checkout, publish branch>
   # edit crates/llm-life-lean/Cargo.toml: add rev = "4d9093b15eb5269308d1d3839a74928a727f240f"
   git add crates/llm-life-lean/Cargo.toml
   git commit -m "crates/llm-life-lean: pin the lean dependency to llm-web's lean-release"
   ```
3. Rebuild everything against the pinned (no-longer-local) dependency, to
   confirm the git rev resolves and nothing silently depended on the local
   `LEAN_PATH` patch:
   ```
   cd <llm-life checkout, publish branch>
   ENGINE_BUILD=<new tag> bash tools/publish-pages.sh
   ```
4. Before pushing `gh-pages`: re-run the publish dry run in a fresh isolated
   clone (same method as `/tmp/llm-life-dryrun` above -- clone locally, no
   local `gh-pages` branch, so it builds its own orphan branch and never
   touches the real one), and redo every check from the dry run in this doc
   (0 leaked-path strings on every wasm and every `.js`, no `web/models`/
   `*.bin` in the export, build tags correct). This is **not optional and
   not the same dry run already done today**: step 3 just rebuilt
   `pkg-lean`/`pkg-lean-mt` from the pinned `4d9093b`, not the `b7e51a2`
   source the dry run and every check in this doc were actually run
   against, so the wasm about to be published has not been checked yet
   until this step runs.
5. Push `publish` to `main` (or merge it there first, a separate decision on branch
   naming) and push the `gh-pages` branch step 3 built (not the throwaway
   clone's from step 4):
   ```
   git push origin publish:main   # or: merge publish into main locally, push main
   git push origin gh-pages
   ```
6. Confirm the live Pages site serves the new build (check the BUILD tag
   in the served `web/index.html`, and that `web/pkg-lean`'s wasm hash
   matches what was built in step 3 and re-verified in step 4).

## `publish-public`: the compiler removed from history, `pages-workflow` merged (2026-10-04, overnight)

Decisions since the above was written: the bit-slice compiler
(`bitslice_ops.py`, `bitslice_compiler.py`, `bitslice_life2_verify.py`,
`bitslice_life2_exhaustive.py`, `bitslice_life2_finetune.py`, their two run
docs, and the two WGSL files nothing on the pages loads) moves to a private
repo (`tritsliced`); training stays in this repo; the exactness claim (one
exact seed, verified on all 33,554,432 possible 5x5 blocks) stays in the
docs, the proof code does not; Pages is built by GitHub Actions
(`pages-workflow`, merged in rather than the manual `tools/publish-pages.sh`,
which is now deleted).

**Scoping constraint (lead's correction, after an earlier attempt rewrote
commits that are already public):** `git filter-repo` ran with
`--refs main..publish` (a range), not whole-branch refs, so `origin/main`'s
own commits never entered the rewrite set and kept their exact hashes.
`origin/main`'s own pre-existing history still has a handful of local
model-cache-path mentions in old README prose -- those are untouched by
design; the *current* files already say the neutral form. The compiler
files never existed on `origin/main`, so nothing private is lost by not
touching it.

Result: `git merge-base --is-ancestor origin/main publish-public` is true,
and `git merge-base origin/main publish-public` equals `origin/main`'s own
hash (`0c237516abcbf069e6afd3b922d5f5488a39f642`) exactly -- a genuine
fast-forward, not a rewrite-and-force-push.
