(ii) "grid -> grid, one channel": jacobi2000's stencil-masked
attention (`jacobi2000::model::Block`, `jacobi2000::mask::Mask::Stencil`,
read-only reference, idea copied not the crate) with one scalar
channel instead of jacobi2000's multi-channel PDE state — this is
jacobi2000 with one channel, said explicitly. `vector::model::StencilOfLife`:
cells enter as floats through a `Linear(1,d)`, **no** positional
embedding (a learned absolute position would break generalisation
the moment the grid size changes), 1-2 stencil-masked attention
blocks (`vector::model::stencil_mask` — additive, 0 for self+8
`life::Grid::neighbor_indices` neighbours, -inf elsewhere, same
toroidal boundary `life::Grid::step` uses), BCE-with-logits per cell.
Trained on a density sweep (0.10-0.50, 9 densities x 8 seeds) of
random 16x16 grids against the true next state; evaluated as an IoU
rollout at 16x16 (in-distribution) **and 32x32** with the identical
trained weights (only the mask tensor rebuilt for the new size) —
the CONCEPT.md §12 generalisation claim.
steps budget: 1200, lr 0.003

## (iii) 3D Life (note, no code)

Extending this to 3D Life changes exactly one thing structurally:
the neighbourhood grows from the 8 Moore neighbours of a 3x3 patch to
the 26 neighbours of a 3x3x3 cube (27 cells including self). Every
piece of this rung's machinery carries over unchanged in kind: (i)'s
attention model becomes a 27-token sequence through the same
`Linear(1,d)` + learned positions + one attention block; (ii)'s
stencil mask becomes a 3D-Moore mask (`life::Grid::neighbor_indices`
generalised to a `width*height*depth` index space, still exactly 26
allowed keys per query, still toroidal, still no positional
embedding so it still generalises across box size). What does *not*
carry over is the zero-parameter floor: a 9-bit index (2^9=512
entries) into a lookup table is free in 2D, but 3D Life's neighbourhood
is 27 bits, and 2^27 = 134,217,728 entries — the table itself becomes
a ~134M-row array (order gigabytes at even one byte per entry,
before any real B/S ruleset like B5766 needs more than 1 bit of
state per cell). The "brute force lookup" rung of the compute ladder
(docs/LADDER.md) simply disappears in 3D: it is no longer a
reasonable thing to build, memory-bound or not. This is exactly the
point CONCEPT.md §12 makes about this project's rungs: the learned
models ((i)/(ii)) generalise to this case with no architectural
change and a parameter count in the hundreds to low thousands, while
"the classical answer" (an explicit table) stops being available at
all. 3D Life becomes jacobi2000's first discrete dataset precisely
because jacobi2000's stencil machinery (a local mask over an
N-dimensional grid) does not care whether N is 2 or 3.

The stencil model's 16² and 32² s/gen are near-identical (0.0011-0.0011s):
one forward pass over a fixed-size dense `[n,n]` mask dominated by
dispatch/kernel-launch overhead at these tiny sizes, not by FLOPs — the same
"memory/dispatch bound, not compute bound" story CONCEPT.md §13 predicts for
the lookup rung, here showing up one rung earlier because these models are
already this cheap at 32². 64² costs more (the `[4096,4096]` mask no longer
hides in launch overhead), still 41-50ms/gen on the 3080 — three orders of
magnitude below the LLM rungs at the same size (2.5-41s from
`docs/runs/2026-09-20-a-rollout.md`/`bert.md`), because the whole grid needs
one forward, not one per cell.
