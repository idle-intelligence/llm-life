llm-life compare

The classical rule and a 512-entry lookup table, next to a language model, two tiny from-scratch models and a stencil-attention model, all computing the same generation from the same starting board. The CPU loop and the lookup table are deliberately naive JavaScript, no Rust, no bit tricks; they are the floor this page measures from, not a benchmark of either one.

output · methods

Game of Life (rule) - Conway's rule: a live cell with two or three live neighbours stays alive, a dead cell with exactly three comes alive, every other cell dies or stays dead. A for loop over the grid on the CPU, one pass per generation.

lookup table - the same rule as a 512-entry table indexed by the 9 neighbourhood bits. The fastest way to compute it, and the thing every model below is measured against.

LLM per cell - a stupid idea: give a language model the rules and one cell's neighbours, ask if it lives or dies. Off the shelf it gets 215 of 512 neighbourhoods right; fine-tuned, all 512.

BERT of Life - alive or dead is a classification. What would a BERT do? A one-layer encoder over the 9 cells as tokens, 3,490 parameters, exact.

9 numbers to centre - drop the language model, keep the approach. A 2-layer MLP over the 9 cell values, 1,442 parameters, exact.

LLM whole grid - cell by cell is stupid. Ask the model for the whole grid in one prompt, one token per cell.

stencil (grid to grid) - the whole grid in one pass, no language model: one attention layer where each cell only sees its 3x3 stencil. 3,329 parameters, trained at 16x16, exact with the same weights at 256x256.
