same computation, six ways to pay for it

The CPU loop and the lookup table below are deliberately naive JavaScript — no Rust, no bit tricks, every cell looked up every generation. They are the floor this page measures from, not a benchmark of either one.

THE RUNGS

CPU loop reads the eight neighbours of every cell with a plain nested loop and counts how many are alive, then applies the original Game of Life rule: a live cell survives with two or three live neighbours, a dead cell is born with exactly three. It has no parameters — it is the definition of the rule, not a model of it — and every other rung on this page is measured against its result.

512-entry lookup packs the same eight neighbours plus the cell itself into a nine-bit number and reads the answer out of a table built once, with all five hundred and twelve possible neighbourhoods precomputed. It has no parameters beyond that table. At the board sizes measured here it costs about the same as the loop above — a single memory read is not obviously cheaper than eight additions until the board is large enough that memory traffic, rather than arithmetic, decides which one wins.

LLM per pixel (adapter) reads one cell's eight neighbours and its own state as a short templated sentence, appended to a shared rules prefix, and asks a half-billion-parameter language model, adjusted with a small trained adapter, to answer with the next state. Every cell gets its own forward pass through the whole model, chunked sixty-four at a time — by far the most expensive way to compute this rule on the page.

LLM batched (adapter) runs the identical forward passes as the row above it — same model, same adapter, same chunks of sixty-four cells — and reaches exactly the same answers. The only difference is what gets written to the log while it runs: this row narrates the shared prefix and the batch mechanism instead of naming one cell at a time, so its cost is the same as the row above it.

BERT of Life is a small transformer encoder, trained from scratch on the rule instead of on language, with one attention layer sixteen numbers wide and thirty-five hundred parameters in total. Each cell's nine neighbourhood values become tokens read by the encoder, which reads out a single answer from the position for the centre cell, and it gets every one of the five hundred and twelve possible neighbourhoods exactly right. It costs far less than either LLM row above it — thousands of parameters instead of hundreds of millions — while still doing one forward pass per cell.

9 numbers -> centre drops tokens altogether: the same nine neighbourhood values enter a small two-layer network as plain numbers, fourteen hundred and forty-two parameters in all, and it also answers every one of the five hundred and twelve neighbourhoods correctly. Removing the embedding and attention machinery that BERT of Life still carries makes this the cheaper of the two per-cell models, one forward per cell either way.

Stencil (grid -> grid) reads the whole board at once instead of one cell at a time: each cell's value becomes a small vector, and one attention layer lets every cell see only its eight grid neighbours, so no position needs to be told to the model beyond that mask. With three thousand three hundred and twenty-nine parameters it scores every case correctly at one board size and then, using the same trained weights, at a board four times as large — it generalises rather than being retrained. Because it takes one pass over the whole board rather than one pass per cell, it is the cheapest of the model rungs here by a wide margin.

Whole-board thinking model is the rung that is not built yet: one very large language model would read the entire board as text and write out the next one directly, with no per-cell structure at all. It needs more memory than a browser tab can give it — more than ten gigabytes — so it would have to run elsewhere, and a single generation would be expected to take minutes rather than milliseconds: by far the most expensive way to compute this rule.
